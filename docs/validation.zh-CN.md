记录截至 **2026-11-11（Asia/Shanghai）**，对象为 [项目硬件表](../README.md#本机硬件) 中这一台 RedmiBook。公开源码、配置和构建入口现已收录；这里将原机历史实测与本次公开构建分开记录。原始私人日志不随仓库发布。

## 本次公开构建：2026-11-11

从固定公开依赖和本机输入重新构建，GPU 可执行文件、Wi-Fi Core／Front 和蓝牙生成补丁分别与原实测版本核对。新的 EFI 装配流程实际运行通过：73 个内容文件、24 个加载项、16 条 Tahoe 内核补丁，四张重新编译的 SSDT 与原机字节一致，x86_64、依赖顺序和 OpenCore 1.0.5 `ocvalidate` 通过。个人 VBIOS 的生成结果也与原机注入副本一致。

蓝牙原生／ASan／UBSan 专项和 Wi-Fi 的 28 个上游用户态场景通过；这些测试不替代物理外设和无线电。可选 UMA 工具的原入口测试和 x86_64 UEFI 构建通过。完整检查摘要见 [publication-checks.json](publication-checks.json)。

公开模板的个人信息脱敏、Darwin 24 项移除和可选日志驱动省略已做代码对比；新的装配包没有安装或重新启动测试。下文是原机历史实测，未完成整机全量测试。

## 候选 23：专项与实机结果

本轮只在显卡二进制和启动配置中加入可控的两区合用模式，沿用此前的绘图命令暂存实现。原生分配成功时保留原结果；原生失败且回退开关开启时，选择苹果原生 type 2 全范围拼块。移除新增开关后恢复候选 22 的下区回退。没有新增内核导入，VCN 仍关闭。

| 检查类型 | 结果 | 能说明什么 |
|---|---|---|
| 构建 / 静态核验 | 构建、原生符号、实际编译 ABI、`ocvalidate` 及 74 个 EFI 启动文件核验通过 | 当前候选构建和实际部署内容符合预期，不等于完整兼容性验收 |
| 原生分配器离线回放 | 合成碎片布局中下区失败 / 全范围成功；6512 页片段解析、大小裁剪、释放及超量失败回滚通过 | 验证生产回退函数与同版原生机器码在合成布局中的行为；不代替实际 GPU 映射 |
| 基础 Metal 实机 | 1024 项计算及 32 × 32 图像的 1024 像素回读正确；1294 字节 render writer 与预期暂存实现一致 | 基础计算、绘图正确，既有命令写入改动生效 |
| 大纹理实机 | 依次持有 1 / 3 / 6 张 2182 × 1394 RGBA16Float Private 纹理，各阶段三轮，共 480 个像素样本正确 | 所测纹理路径的样本正确性；不是所有纹理或 WindowServer 资源的完整验证 |
| 窗口切入 | 五应用 15 次、访达 / Safari 6 次，前台及主窗口可见均核验，始终位于同一桌面 | 21 次操作确实发生；不直接测量视觉流畅度或 FPS |
| 两区回退运行记录 | 一个 WindowServer 申请取整为 851968 字节；下区 720896、上区 131072 字节，各自不足、合计恰好够，最终返回成功 | 至少一个对应情形的实机分配回退成功；未逐资源关联后续像素，也未取得至少 16 MiB 的最终大块回退记录 |

窗口轮次的全 GPU 回收等待累计量分别为 131.693 ms（五应用）和 68.067 ms（访达 / Safari），GPU 恢复计数均为 0。这些是阶段累计计数，不是每帧卡顿时长。与旧候选的页面、预热和启动时长不同，不能换算严格改善百分比或 FPS。

用户反馈“好像流畅了一点？反正卡顿没那么糟糕了”。这支持带不确定性的部分体感改善，不支持“Safari 卡顿已解决”。完整候选 22 恢复材料已核验保留，但本轮没有执行 23 → 22 恢复。
